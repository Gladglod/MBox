# MBox（手机竖屏版）

基于 [TVBoxOS](https://github.com/q215613905/TVBoxOS) 改造的 **手机竖屏** 客户端（纯 XML + Java，无 Compose，包名 `com.github.tvbox.osc`）。
本仓库在原生 TV 交互之上重做了详情页与播放器，使整体适配手机触摸操作。

## 构建

```bash
# Windows
gradlew.bat :app:assembleJava64Debug
```

产物：`app/build/outputs/apk/java64/debug/TVBox_debug-java64.apk`

## 首页

顶部是「分类页签 + 分页内容」的横向结构，页签左侧第一项固定为 **热门推荐**，也是启动应用后默认停留的页面。

### 顶栏

顶栏只做两件事，**没有页面标题**——紧挨着的页签条已经在指示"当前在第几页"，再叠一行同名标题是重复：

- **左：假搜索框**（`searchBar`）。整块可点，进搜索页；首页不抢键盘焦点，真输入框留给搜索页。
- **右：数据源胶囊**（`tvMenu`）。文字就是当前站点名（不再是「换源」这种行话），点开切换；
  只有一个站点时自动去掉箭头并置为不可点，避免做成死按钮。
- 切源期间胶囊轻微呼吸（`startSourceChipBlink()`），替代原来那行每秒刷新的日期。
  手机上状态栏自带时间，那个 `yyyy/MM/dd E HH:mm` 是 TV 版遗留，已移除。

### 内容

- **热门推荐**（`HotRecommendFragment`）：网格展示首页接口返回的推荐列表（`AbsSortXml.videoList`）；
  当「界面偏好 → 首页推荐」选成「历史记录」时改读本地播放记录（最多 30 条，带「上次看到 x 集」）。
  列表按批追加：首批 12 条，滑到底再补 12 条，不会一进首页就把几十张海报一次性丢给 Glide。
  - **空推荐兜底**：不少数据源的 `homeContent` 根本不返回推荐列表，此时自动退回本地观看历史，
    避免默认落地页是一片「暂无推荐内容」；历史也为空时才显示提示文案 + 一个「换个数据源」按钮
    （`HomeActivity.onHomeEmptyAction()`：可切站点多于 1 个就弹列表，否则直接进数据源地址页）。
  - **间距**：与分类页共用 `GridSpacingItemDecoration(8dp)`，落地页不再是 0dp 紧贴。
  - **标题两行**：`item_grid` 的 `tvName` 允许 2 行，中文长片名不再被截成一个省略号。
- **加载态是骨架屏不是转圈**（`HomeSkeletonCallback` + `loadsir_home_skeleton`）：
  LoadSir 挂在内容区而不是顶栏，骨架按真实网格尺寸先占位（页签条 44dp + 三列海报位），
  数据回来后原地替换，不会整块跳一下。
- **标签可编辑**：「我的 → 界面偏好 → 首页标签」（`HomeTabSettingActivity`）
  - 勾选决定某个分类是否出现在首页，**长按拖动**调整顺序，底部有「全选 / 全不选 / 恢复默认」。
  - 配置存 `HawkConfig.HOME_TABS`（每行 `可见(1/0)\t分类id`，行序即页序），换数据源后新增的分类会自动追加到末尾并默认显示。
  - 保存返回后首页在 `onResume` 里检测到配置变化，重建页签与页面，无需重启。
- **左右滑动**切换页面时顶部页签会同步跟随；从「分类」页点某个分类会跳到首页对应页签。


## 详情页

- **预览播放器**：进入详情页后播放器内嵌在页面顶部，随内容滚动做位移；不再自动滚动到选集区，进入即停在页面最顶部。
- **点击预览区域**：只**显示/隐藏播放组件**（退出、投屏、菜单、播放/暂停、下一集、弹幕、倍速、全屏），**不会**自动进入全屏。首次点击会先拉起播放。
- **预览热区**：`previewPlayerBlock` 是盖在播放器上的透明热区，控制条显示时自动隐藏，避免挡住控制条按钮。
- **选集**：单行横滑，右侧「正序 / 倒序」一键切换排序。
- 移除了「立即播放」按钮，简介下方直接是「收藏 / 换源 / 搜索 / 简介」操作行。

### 全屏与退出

- **全屏按钮**：进入全屏（横屏铺满，隐藏系统状态栏/导航栏）；再点一次退出全屏回到详情页。
- **左上角退出按钮**：
  - **全屏状态下** → 退出全屏，回到详情页；
  - **非全屏状态下**（详情页内嵌播放）→ 退出当前播放（离开详情页）。

### 「⋮」设置抽屉

- **横屏**：从右侧向左滑出；
- **竖屏**：从底部向上滑出。

抽屉内容：

1. **播放器 / 解码 / 画面比例** —— 内联下拉列表（不再用系统 `PopupMenu`，尺寸与配色跟随抽屉）。
2. **片头片尾** —— 点击记录当前位置；长按后左右滑动微调（每 14dp = 1 秒）；旁边是重置按钮。
3. **弹幕设置** —— 当前在线弹幕源名称、弹幕颜色、速度、字号、行数、透明度，以及「搜索弹幕」入口。
4. **其他** —— 播放重试 / 刷新、字幕、音轨、视频轨、横竖屏切换、屏显开关、解析线路。

## 适配说明

- AutoSize 设计基准：竖屏按 **360dp** 宽；横屏按 `360 × 屏宽/屏高` 折算，保证横竖屏 density 一致，避免横屏下 UI 被整体放大。
- 分类列表（`GridFragment`）在页面滑走时释放视图与数据，滑回时重建，避免多 Tab 常驻导致内存溢出。
- 弹幕搜索对话框自适应屏幕：限宽 `min(90% 屏宽, 430dp)`、限高 `min(86% 屏高, 560dp)`。
- 「我的 → 数据源地址」已改为独立页面，不再使用 `dialog_api` 弹窗；该弹窗本身也重排成竖排
  （二维码 110dp 居中在上 + 地址 + 历史直播/存储权限 + 点播/直播地址 + 确定，288dp 宽），仅旧的 TV 设置页还在用。
- 背景优先级：自定义配图（`files/wp`）> 纯色（`HawkConfig.WALLPAPER_COLOR`）> 默认 `app_bg`。
  设置页里选完立即生效（`BaseActivity.applyWallpaperNow()`），其他页面在 `onResume` 时自动跟随。

## 性能与内存

首页列表是图片密集页面，按「列表底座 → 图片加载 → 回顶控制」三层做优化。

### 一、RecyclerView 底座

- **ViewHolder 复用**：全部列表走 `BaseQuickAdapter`，`onCreateViewHolder` 只 inflate、`convert()` 只赋值。
- **bind 期不做重活**：URL 解析、`RequestOptions` 组装、`SimpleDateFormat` 格式化都移到了缓存或数据准备阶段
  （收藏时间是固定的，按条目 id 缓存文案，不再每次 bind 都 `new Date()` + `format()`）。
- **`setHasFixedSize(true)`**：条目高度固定的列表全部打开——首页分类网格、热门推荐、播放历史、收藏、
  分类页、首页标签编辑页。这样数据变化时 RecyclerView 会跳过重新测量。
- **关闭增删动画**：`setItemAnimator(null)`，一次 `setNewData` 几十项时动画会明显掉帧。
- **分页懒加载**：`HomePageAdapter` 不再预先 `new` 出所有分类页，只在 ViewPager 真正需要某一页时回调
  `PageProvider.create(position)` 创建；页面滑出 `offscreenPageLimit`（=1）后按默认实现 `detach`，
  视图树随之销毁（`GridFragment` / `HotRecommendFragment` 的 `isKeepViewOnDestroy()` 返回 false，
  `rootView` 置空），滑回来再重建并按需重新拉数据。以前这里重写成了 `hide()`，滑过的页面
  RecyclerView + 海报 bitmap 会一直留着，分类一多就容易 OOM。
- **分批渲染**：热门推荐首批只渲染 12 条，滑到接近底部再追加下一批。

### 二、图片加载（复用与取消）

- **全局单例**：所有请求统一走 `Glide.with(App.getInstance())`，不存在多个 ImageLoader 导致缓存分裂。
- **复用自动取消**：`into(ImageView)` 是 Glide 的标准用法，View 被复用时上一次请求会被自动取消，
  不会出现「旧图覆盖新图」的错位。
- **跳过重复请求**：`ImageView` 用 tag 记住当前图片地址，复用到同一个 item 时不再重复发起 Glide 请求。
- **按显示尺寸解码（最关键的一条）**：`ImgUtil.load()` 的宽高参数统一传 `0, 0`，**不调用 `override()`**，
  让 Glide 的 `ViewTarget.SizeDeterminer` 等 View 测量完再按实测尺寸解码。
  以前传的是 `mm2px(244dp) × mm2px(320dp)`——那是 TV 版 4 列布局的设计稿尺寸，
  手机 3 列时海报实际只有约 146×243px，而解码成了 366×480px，**面积差 5 倍**（1080p 手机上同样差 4~5 倍）。
- **网格海报不再让 Glide 切圆角**：`item_grid` 的 `posterFrame` 本身有 `bg_poster` + `clipToOutline`，
  圆角由它负责；再让 Glide 用 `RoundedCorners` 复制一张全尺寸 bitmap 纯属浪费。
  列表模式（`item_list`）没有 outline，才传圆角半径。
- **`RequestOptions` 缓存**：按「尺寸 + 圆角 + 是否铺满」缓存复用（列表里只有几档组合），
  不再每次 bind 都 new 一堆 `Transform`。
- **model 缓存**：`URL → GlideUrl` 用 `LruCache(256)` 缓存。原来每次 bind 都要对图片地址做
  `split` / `URLDecoder` / Gson 解析 `@Headers=`、`@Cookie=` 这些后缀，是 `onBindViewHolder` 里的隐形开销。
- **磁盘缓存**：`OkHttpAppGlideModule` 显式指定 300MB 磁盘缓存（`glide_cache`），
  「首页 → 详情 → 返回」不会重复走网络。
- **内存缓存上限**：2 屏内存缓存 + 3 屏 bitmap 池，不超过可用内存 20%。
- **占位图**：文字占位图按「首字 + 尺寸」缓存（`LruCache` 上限 48），只在加载失败时才生成；
  尺寸未知时用 `ColorDrawable`，不再为「未知尺寸」专门造一张 180×240 的 bitmap。
- **不要在滚动时 `Glide.pauseRequests()`**（曾经踩过的坑，已移除）：
  pause 会让滚动过程中新出现的 item 永远拿不到图，表现就是「图片一直加载不出来」；
  松手瞬间几十个请求同时 resume，又反过来抢占主线程。Glide 本身会在 View 复用时自动取消旧请求。

### 二·一、实测对照（540×960 / density 240 模拟器）

同一台设备、同一份数据源、同样 20 次快速滑动，只切换「是否强制 override 366×480」：

| 指标 | 旧：强制 override | 新：按 View 实测尺寸 |
| --- | --- | --- |
| Janky frames | **100%** | **0.48%** |
| 50th percentile | 101ms | 11ms |
| 90th percentile | 150ms | 18ms |
| 99th percentile | 200ms | 22ms |
| Slow bitmap uploads | 64 | 0 |
| Native Heap | **318MB** | 16MB |
| TOTAL PSS | 511MB | 197MB |

旧行为下每帧要花 100ms 以上、并且 bitmap 内存直接顶到 300MB+，这正是「图片加载慢 / 没加载完 / 滑动卡顿」
以及更早之前「首页一次性加载太多导致闪退」的同一个根因。

### 三、平滑回到顶部

`SmoothTopScroller`（`ui/widget`）继承 `LinearSmoothScroller`：

- 用 `SNAP_TO_START` 强制把 0 号 item 的顶部对齐到列表内边距顶部——
  这正是 `smoothScrollToPosition(0)` 的短板：0 号 item 只露一半时它判定「已可见」就不动了。
- 速度用 `calculateSpeedPerPixel()` 按「每英寸毫秒数」控制，默认 28ms/inch（框架是 25ms），收尾更从容。
- 距离顶部超过 12 条时直接 `scrollToPosition(0)` 跳过去：平滑滚过几十屏会把中间所有海报都加载一遍，反而更卡。
- 已在顶部（`canScrollVertically(-1) == false`）时返回 `false`，调用方可以据此判断要不要消费这次事件。

触发入口：

| 位置 | 操作 |
| --- | --- |
| 首页 | 再次点击当前分类页签 |
| 首页 | 已经在首页时再点底部「首页」 |
| 热门推荐 | 按返回键（已上滑时先平滑回顶，不退出） |
| 播放历史 / 收藏 | 点击顶部标题 |

## 弹幕

- 弹幕层 `DanmakuView` **必须等布局完成（宽高 > 0）再 `prepare()`**，否则库内部会把所有弹幕判定为
  "超出屏幕"，表现为一条都不显示。`DanmuLoadController` 里做了尺寸重试 + 布局回调兜底。
- 拖动进度后需要主动重新加载弹幕：普通 `seekTo` 不会触发 `prepared()` 回调，
  所以 `onDanmuSeek` 里会延迟重试若干次。
- **自定义接口**：「我的 → 弹幕设定 → 弹幕接口」可填自定义地址，点「测试」会用它真实搜索一次
  「庆余年 第 1 集」，直接在对话框里显示「✔ 接口正常，匹配到 N 条弹幕」或具体错误原因；
  测试通过即生效，无需再点确定。留空点「测试」则验证内置接口。
- 排查弹幕问题可过滤日志：`adb logcat -s echo-danmu`，关键输出：
  `parsed count`（解析条数）、`start at`（是否启动）、`view size still 0`（布局未就绪）、`empty after parse`（解析为空）。
